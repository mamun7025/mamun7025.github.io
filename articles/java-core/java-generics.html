Java Generics — Classes & Methods

Generics let you write classes and methods that work with any type while keeping full compile-time type safety — no casting, no ClassCastException surprises at runtime.

Why generics exist

  • Type safety — errors are caught at compile time instead of blowing up at runtime.
  • No casting — the compiler already knows the type, so you skip explicit casts.
  • Reusable code — one class/method handles many types instead of duplicating logic.
Note: Java generics only work with reference types, not primitives. Use the wrapper types — Integer, Double, Boolean — instead of int, double, boolean.

1 · Generic Class

A class that declares one or more type parameters in angle brackets right after the class name.

Single type parameter <T>
public class Printer<T> {          // T = type parameter

    private T thingToPrint;

    public Printer(T thingToPrint) {
        this.thingToPrint = thingToPrint;
    }

    public void print() {
        System.out.println(thingToPrint);
    }
}
Usage — the type is chosen by the caller
Printer<String>  p1 = new Printer<>("Hello");
Printer<Integer> p2 = new Printer<>(2025);
p1.print();   // Hello
p2.print();   // 2025

Multiple type parameters

A class can declare several type parameters, conventionally named T, V, K, E.

public class Pair<T, V> {
    private T first;
    private V second;

    public Pair(T first, V second) {
        this.first  = first;
        this.second = second;
    }
}

Pair<String, Integer> user = new Pair<>("age", 33);

Bounded type parameter  <T extends Animal>

Restricts T to a type (or subtype). Now T can only be an Animal — e.g. Cat, Dog — and you can safely call Animal's methods on it.

public class Cage<T extends Animal> {
    private T animal;

    public void makeSound() {
        animal.sound();   // allowed: T is guaranteed to be an Animal
    }
}
🧠extends = "this type, or anything below it in the hierarchy."

2 · Generic Method

A single method can be generic even inside a non-generic class. The type parameter goes right before the return type.

Java
public class Printer {

    // <T> declared right before the return type (void)
    private static <T> void print(T thing) {
        System.out.println(thing);
    }

    // two type parameters
    private static <T, V> void print(T a, V b) {
        System.out.println(a);
        System.out.println(b);
    }

    // returning a generic type (returns T)
    private static <T, V> T printAndReturn(T a, V b) {
        System.out.println(a);
        System.out.println(b);
        return a;
    }
}

3 · Wildcards <?>

A wildcard ? means "some unknown type." Handy when the method only reads from a collection and doesn't care about the exact element type.

Unbounded & bounded wildcards
// unbounded — accepts a List of ANY type
private static void print(List<?> list) {
    System.out.println(list);
}

// upper-bounded — a List of Animal or any subtype
private static void printAnimals(List<? extends Animal> list) {
    for (Animal a : list) a.sound();
}

// lower-bounded — a List of Integer or any supertype
private static void addNumbers(List<? super Integer> list) {
    list.add(42);
}
PECS rule: Producer extends, Consumer super. Read from a structure → use ? extends; write into it → use ? super.
