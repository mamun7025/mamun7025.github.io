hashCode() & equals()

These two Object methods decide when two objects are considered "the same." Hash-based collections like HashMap and HashSet rely on both — get them wrong and lookups silently break.

  • equals() — decides whether two objects are logically equal. The default checks reference identity (==).
  • hashCode() — returns an int "bucket number" for the object. The default is derived from the object's identity, not its contents.

Hash collections first jump to the bucket given by hashCode(), then use equals() to find the exact match inside that bucket. Comparing hash codes is roughly 20× faster than a full equals(), which is why the hash comes first.

The contract

If you override one, you must override the other — otherwise you break this contract.

  1. If a.equals(b) is true, then a.hashCode() == b.hashCode() must be true.
  2. The reverse is not required — equal hash codes do not imply the objects are equal (that's a hash collision, and it's allowed).
  3. hashCode() must return the same value on repeated calls, as long as the fields used in equals() don't change.
  4. Unequal objects may share a hash code — but spreading them out gives better performance.
🧠Equal objects → equal hash codes. Always. Equal hash codes → maybe equal.

Without overriding — the trap

Two objects with identical content are treated as different, because the defaults compare identity.

public class Character {
    private String name;
    public Character(String name) { this.name = name; }
}

Character c1 = new Character("Arnold");
Character c2 = new Character("Arnold");

System.out.println(c1.hashCode());   // 1595428806
System.out.println(c2.hashCode());   // 1072408673  (different!)
System.out.println(c1.equals(c2));   // false
1595428806
1072408673
false

Put both into a HashSet and you'd get two entries, even though they represent the same character.

With both overridden — correct

public class Character {
    private String name;
    public Character(String name) { this.name = name; }

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof Character)) return false;
        Character other = (Character) o;
        return Objects.equals(name, other.name);
    }

    @Override
    public int hashCode() {
        return name == null ? 0 : name.hashCode();
    }
}

Character c1 = new Character("Arnold");
Character c2 = new Character("Arnold");

System.out.println(c1.hashCode());   // 1969563338
System.out.println(c2.hashCode());   // 1969563338  (same!)
System.out.println(c1.equals(c2));   // true
1969563338
1969563338
true

The clean way — Objects.hash()

For multiple fields, don't hand-roll the 31 * result + ... arithmetic (it's easy to get the operator precedence wrong). Let java.util.Objects do it.

public class Person {
    private final String firstName;
    private final String lastName;
    private final LocalDate dob;

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof Person p)) return false;
        return Objects.equals(firstName, p.firstName)
            && Objects.equals(lastName, p.lastName)
            && Objects.equals(dob, p.dob);
    }

    @Override
    public int hashCode() {
        return Objects.hash(firstName, lastName, dob);
    }
}
Tip: use exactly the same fields in equals() and hashCode(). Your IDE and Lombok's @EqualsAndHashCode can generate both correctly for you.

ExpressionResult / note
