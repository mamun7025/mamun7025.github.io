Most Used Git Commands

The Git commands I actually use every day, grouped by task, plus two routines: syncing your branch in the morning and pushing changes safely.

Everyday basics Branching & comparing Workflows
Branch names used below: main is the shared branch and feature/my-work is your personal working branch. Replace them with your own.

Quick reference

CommandWhat it does
git statusShow changed, staged and untracked files
git add <file>Stage a file for the next commit
git commit -m "msg"Record staged changes
git pullFetch and merge the remote branch
git pushUpload local commits to the remote
git fetch origin mainDownload remote changes without merging
git checkout -b <name>Create and switch to a new branch
git merge <branch>Merge another branch into the current one
git diff A..B --name-onlyList files that differ between two branches
git stash push -- <file>Temporarily shelve changes to a file
git log -p <file>Full change history of one file

1 · Everyday basics

Check what changed, stage only what you mean to commit, then push.

git pull                                  # start from the latest remote state
git status                                # what changed?

git add src/pages/sales-report.js src/pages/sales-report.html
git add src/pages/order-list.html
git status                                # confirm what is staged

git commit -m "CMS: add date filter to sales reports"
git push
🧠Stage files by name instead of git add . so stray debug files or local config never end up in a commit.

2 · Branching

A cheap backup branch before risky work, and merging the shared branch into yours.

git checkout -b bkp-sep-30                # snapshot of the current state

git checkout main
git pull                                  # update the shared branch

git checkout feature/my-work
git merge main                            # bring main's changes into your branch
Tip: newer Git versions also have git switch <branch> and git switch -c <new-branch>, which only switch branches. checkout can also restore files, so switch is harder to misuse.

3 · Comparing changes

See what differs before you merge, or trace how a single file changed over time.

Between two branches

git diff main..feature/my-work --name-only                # just the file names
git diff main..feature/my-work                            # full diff
git diff main..feature/my-work -- src/dao/OrdersDAO.java  # one file only

Against the remote (without merging)

git fetch origin main
git diff origin/main -- src/dao/OrdersDAO.java

History of one file

git log -p src/utils/ErpUtil.java         # every commit with its patch

4 · Stash — park local changes

Useful when git pull refuses to run because a local edit would be overwritten.

git stash push -- src/core/app-constants.js   # shelve just this file
git pull
git stash pop                                 # re-apply the shelved change

git stash list                                # see what is stashed

5 · Workflow: before starting work in the morning

Take a backup, update main, review what is new, then merge it into your branch.

git checkout -b bkp-sep-22                    # 1. safety backup of yesterday's work

git checkout main                             # 2. update the shared branch
git pull

git checkout feature/my-work                  # 3. review incoming changes
git diff main..feature/my-work --name-only
git diff main..feature/my-work

git merge main                                # 4. merge and re-check
git diff main..feature/my-work

6 · Workflow: before pushing to the remote

Commit on your branch, merge into main, pull, resolve any conflicts, then push.

git status                                    # 1. commit on your branch
git add src/core/JsClient.js src/pages/sales-report.js
git commit -m "CMS: daily/weekly/monthly/yearly reports"

git checkout main                             # 2. merge into main
git merge feature/my-work
git status

git pull                                      # 3. get anything pushed meanwhile
                                              #    resolve conflicts here if any
git push                                      # 4. publish
Conflicts? Fix them before git push. A visual merge tool makes this much easier, see Git MergeTool & DiffTool Config.

Bonus · Save your shell history

history                                       # list recent commands
history > history_for_print.txt               # save them to a file
