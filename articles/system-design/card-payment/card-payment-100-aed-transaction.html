System Design · Payments

A 100 AED Card Payment, End to End

You pay with your Mashreq Visa card at Safari Mall for 100 AED. In under two seconds the terminal says Approved, but the money only moves the next day. This note follows that one transaction through two banks, two different card processors and one card network.

The parties

Seven parties take part in one payment. The two processors are separate companies, one on each side of the network.

Why the processors are different companies

Running a PCI DSS-certified switch, HSMs and a 24/7 network connection is expensive, so each bank uses a dedicated processing company:

  • The acquirer chose Network International to handle merchants and terminals.
  • The issuer uses NEOPAY, Mashreq's payments company, to handle its cards.
  • The two processors never talk to each other directly. Visa sits between them. Each processor is connected to VisaNet as an agent of its bank, so Visa is the only common point.

This is the main difference from an "on-us" transaction, where card and terminal belong to the same bank and processor and the request may never leave that processor's switch.

Phase 1 · Authorization (real time)

Step by step: the 100 AED authorization

Every hop speaks a dialect of ISO 8583. The request is an 0100 (or 0200 for single-message debit) and the response is an 0110.

1 · Card at the terminal Safari Mall

The cardholder inserts the card and enters the PIN. The chip and the terminal run the EMV transaction:

  • The terminal reads the card number (PAN), expiry and the card's application data.
  • The chip generates an ARQC cryptogram, a one-time signature over the amount (100.00), currency (784 = AED), date and a random number. Only the issuer side can verify it.
  • The PIN is encrypted inside the PIN pad as a PIN block and never leaves it in clear text. (A contactless tap under the UAE limit of 500 AED would skip the PIN; the rest of the flow is the same.)

2 · Terminal → acquirer processor Network International

The terminal is registered to Emirates NBD but physically connects to Network International's switch. Network International:

  • Checks the terminal ID and merchant ID (MID) against Emirates NBD's merchant records, and checks that Safari Mall is active and allowed to accept Visa.
  • Runs the acquirer's fraud and velocity rules (for example, too many declines on this terminal).
  • Reads the BIN (first 6–8 digits). It is a Visa card and it is not on-us because Mashreq is not an Emirates NBD BIN, so the request has to go to Visa.
  • Translates the PIN block in its HSM, from the terminal key to the key shared with Visa (the acquirer working key).
  • Builds the Visa-format 0100 message.
Key fields in the 0100 request (simplified)
# ISO 8583 authorization request — sent by Network International to Visa
MTI   0100                    # authorization request
DE 2  4xxxxx******1234        # PAN (masked here)
DE 3  000000                  # processing code: purchase from default account
DE 4  000000010000            # amount 100.00 (minor units, 2 decimals)
DE 7  1018143205              # transmission date/time (MMDDhhmmss, GMT)
DE 11 482913                  # STAN — system trace audit number
DE 22 051                     # POS entry mode: chip read, PIN entered
DE 32 4xxxxx                  # acquiring institution ID (Emirates NBD)
DE 37 629114482913            # RRN — retrieval reference number
DE 41 SFM00017                # terminal ID
DE 42 SAFARIMALL0001          # merchant ID
DE 43 SAFARI MALL SHARJAH AE  # merchant name / location
DE 49 784                     # transaction currency: AED
DE 52 [encrypted PIN block]
DE 55 [EMV data incl. ARQC]

3 · Visa routes the request VisaNet

  • Looks up the BIN in its routing tables and finds that the BIN belongs to Mashreq, whose processing endpoint is NEOPAY.
  • Translates the PIN block again, from the acquirer zone key to the issuer processor's zone key.
  • Runs network-level risk scoring (Visa Advanced Authorization) and adds a risk score to the message.
  • Forwards the 0100 to NEOPAY's VisaNet endpoint.
🔐Why the PIN is re-encrypted at every hop: each pair of parties shares its own key, so no single key opens the PIN block end to end. With two different processors this gives three key zones: terminal ↔ Network Intl, Network Intl ↔ Visa, Visa ↔ NEOPAY. Only NEOPAY's HSM can check the PIN against Mashreq's PIN keys.

4 · Issuer processor checks the card NEOPAY

NEOPAY acts for Mashreq and runs the card-level checks in its HSMs and authorization engine:

  • Card status: active, not expired, not reported lost or stolen.
  • ARQC verification: confirms the chip is genuine and the amount was not changed on the way. NEOPAY then creates an ARPC for the response.
  • PIN verification: checks the PIN block against the PIN offset or PVV, and counts wrong PIN tries.
  • Card limits and controls: daily POS limit, e-commerce or country blocks, merchant category (MCC) rules.

What happens next depends on how Mashreq set up the integration:

ModelWho checks the balanceTypical for
Online to core bankingNEOPAY calls Mashreq's core banking or card management API, and Mashreq checks the account and places the holdDebit cards (money sits in a current account)
Processor-hosted balanceNEOPAY keeps the open-to-buy or credit limit and decides alone; Mashreq gets the result in a file or feedCredit and prepaid cards

5 · Issuing bank decides Mashreq

  • Checks the available balance: is it at least 100 AED?
  • Runs the bank's own fraud model (unusual location, amount, time of day).
  • Approves and places a 100 AED authorization hold. The available balance goes down, but the ledger (book) balance does not change yet.
  • Returns approval code DE 38 = 7Q2K9B and response code DE 39 = 00 (approved).
Mashreq account right after authorization
Ledger balance      5,000.00 AED   # unchanged
Holds                 100.00 AED   # SAFARI MALL — pending — auth 7Q2K9B
Available balance   4,900.00 AED   # what the mobile app shows as "available"

6 · The response travels back 0110

The 0110 goes back the same way: Mashreq → NEOPAY (adds ARPC) → Visa → Network International → terminal. Network International stores the approved transaction in its transaction log, because it will need it for clearing tonight. The terminal shows Approved and prints the receipt.

Phase 2 · Clearing (batch, end of day)

Clearing: turning the hold into a debit

Authorization only reserved the money. Clearing is when the acquirer says: "this sale really happened, here is the final amount."

  1. Terminal batch close. At end of day Safari Mall's terminal (or Network International automatically) closes the batch. Our 100 AED sale goes in with all of the day's other approved sales.
  2. Acquirer processor builds the clearing file. Network International creates a Visa BASE II clearing record (TC05 sales draft) for each sale. Each record keeps the RRN, approval code 7Q2K9B, amount 100.00 AED and MCC.
  3. Visa clears. Visa receives files from every acquirer, works out the interchange for each record, sorts records by issuer and sends NEOPAY the records for Mashreq's cards.
  4. Issuer processor matches. NEOPAY matches each record to its authorization using the approval code, PAN and amount, then passes the posting to Mashreq.
  5. Issuer posts. Mashreq releases the hold and posts the actual 100 AED debit.
Mashreq account after clearing (T+1)
Ledger balance      4,900.00 AED   # now debited
Holds                   0.00 AED   # hold 7Q2K9B released
Available balance   4,900.00 AED   # unchanged for the customer
🧠Why the app shows "pending" for a day: between authorization and clearing the transaction exists only as a hold. Holds that are never cleared (for example, a hotel pre-authorization that was never completed) expire after a set number of days and the money comes back on its own.
Phase 3 · Settlement (the money moves)

Settlement: who pays whom

Visa does not move 100 AED by itself. It nets every bank's position for the day and moves one amount per bank through settlement accounts. Processors only provide data and reports; they never hold the funds.

  1. Visa calculates Mashreq's net amount owed for the day (all its cardholders' purchases minus interchange earned) and Emirates NBD's net amount due (all its merchants' sales minus interchange paid).
  2. Mashreq's settlement bank pays its net amount in AED into Visa's settlement account.
  3. Visa pays Emirates NBD's settlement account.
  4. Emirates NBD credits Safari Mall's merchant account, minus the Merchant Discount Rate (MDR). Depending on the merchant agreement this is T+1 or T+2.

When things go wrong

Having two processors means two more places where a message can get lost. The system is designed so that the cardholder is never charged for a sale that did not happen.

Timeout: the response never reaches the terminal

Mashreq approved and placed the hold, but the 0110 was lost between Visa and Network International. The terminal shows Declined / No response.

  • Network International sends an automatic reversal (0400) with the same STAN and RRN.
  • Visa forwards it to NEOPAY, and Mashreq releases the 100 AED hold.
  • If the reversal is lost too, the hold has no clearing record and expires by itself.

Issuer processor unavailable: Visa stand-in (STIP)

If NEOPAY or Mashreq's core banking does not reply in time, Visa can decide for Mashreq using Stand-In Processing limits that Mashreq set in advance (for example, approve up to 500 AED if the card is not blocked). Visa then sends the stand-in decision to NEOPAY as an advice (0120) when the connection comes back, so Mashreq can place the hold afterwards.

Decline

Wrong PIN (55), insufficient funds (51), expired card (54) or suspected fraud (59). No hold, no clearing, no money moves. Only a decline record is kept for fraud analytics.

Refund or chargeback later

  • Refund: Safari Mall starts a refund, Network International clears a credit record (TC06), and the money runs the same path in reverse.
  • Chargeback: the cardholder disputes the charge with Mashreq. NEOPAY raises it through Visa Resolve Online, Network International passes it to Emirates NBD, and Emirates NBD asks Safari Mall for proof (the receipt with approval code 7Q2K9B).

Key points

  • Processors work for banks, not for each other. Network International and NEOPAY only meet inside VisaNet. Each is the technical agent of its bank on Visa.
  • Authorization is real time and moves no money. It creates a hold. The available balance drops right away; the ledger balance drops after clearing.
  • Clearing and settlement are batch jobs. Records are matched to authorizations by approval code, RRN and PAN, and banks settle one netted amount per day.
  • Security is split by zones. PIN blocks are re-encrypted at each hop, and only the issuer processor can verify the PIN and the EMV cryptogram.
  • Processors are paid by invoice. Interchange and MDR come out of the 100 AED; processor and scheme fees are billed to the banks separately.
  • Failures resolve to "no charge". Reversals, stand-in advices and hold expiry make sure a lost message does not leave a wrong debit.
