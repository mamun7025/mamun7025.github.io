Java Builder Pattern

The Builder pattern constructs a complex object step-by-step through a fluent API — ideal when a class has many parameters, several of them optional.

The problem it solves

A telescoping constructor with many arguments is error-prone: the types are similar, the order is easy to get wrong, and optional values must be passed as null.

Hard to read — what does each argument mean?
Computer pc = new Computer("500 GB", "2 GB", true, false);
  • Too many arguments → easy to swap by mistake.
  • Optional parameters still have to be supplied (often as null).
  • Complex construction logic leaks into the caller / factory.

How to implement it

  1. Create a static nested Builder class that mirrors the outer class's fields.
  2. Put the required attributes in the Builder's constructor.
  3. Add a setter per optional attribute that returns the Builder (this) so calls chain.
  4. Add a build() method that returns the finished object via a private constructor taking the Builder.

Approach 1 — required params in the Builder constructor

Java
public class Computer {

    // required
    private final String hdd;
    private final String ram;
    // optional
    private final boolean graphicsCard;
    private final boolean bluetooth;

    private Computer(Builder b) {
        this.hdd          = b.hdd;
        this.ram          = b.ram;
        this.graphicsCard = b.graphicsCard;
        this.bluetooth    = b.bluetooth;
    }

    public static class Builder {
        private final String hdd;      // required
        private final String ram;      // required
        private boolean graphicsCard;   // optional
        private boolean bluetooth;      // optional

        public Builder(String hdd, String ram) {
            this.hdd = hdd;
            this.ram = ram;
        }

        public Builder graphicsCard(boolean v) { this.graphicsCard = v; return this; }
        public Builder bluetooth(boolean v)    { this.bluetooth = v;    return this; }

        public Computer build() { return new Computer(this); }
    }
}
Usage
Computer pc = new Computer.Builder("500 GB", "2 GB")
        .bluetooth(true)
        .graphicsCard(true)
        .build();

Approach 2 — fluent builder() entry point

A slightly cleaner style where a static builder() method starts the chain and every field is optional/fluent.

Java
public class Customer {

    private final String name;
    private final String email;
    private final String phone;

    private Customer(Builder b) {
        this.name  = b.name;
        this.email = b.email;
        this.phone = b.phone;
    }

    public static Builder builder() { return new Builder(); }

    public static class Builder {
        private String name, email, phone;

        public Builder name(String v)  { this.name = v;  return this; }
        public Builder email(String v) { this.email = v; return this; }
        public Builder phone(String v) { this.phone = v; return this; }

        public Customer build() { return new Customer(this); }
    }
}
Usage — reads like a sentence
var customer = Customer.builder()
        .name("Mamun")
        .email("mamun@gmail.com")
        .phone("+9711234567")
        .build();

In practice: Lombok's @Builder

In Spring Boot projects you rarely hand-write all this boilerplate — Lombok generates the entire builder from a single annotation.

@Getter
@Builder
public class Customer {
    private String name;
    private String email;
    private String phone;
}

Customer c = Customer.builder().name("Mamun").email("a@b.com").build();
🧠Builder = build a complex object step-by-step — readable, order-independent, and immutable once built.
